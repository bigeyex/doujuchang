# 架构

豆剧场将创作数据、编辑器和游戏播放器分开。项目目录是创作数据的来源，Web 编辑器读写这些普通文件；Cocos 播放器负责实际游戏的画面、输入和视听效果。

| 部分 | 主要位置 | 职责 |
| --- | --- | --- |
| React 编辑器 | `src/App.jsx`、`src/editor/` | 页面切换、素材管理、CodeMirror 剧本编辑和静态界面画布。 |
| 本机项目服务 | `scripts/server.mjs`、`scripts/project-store.mjs` | 读写项目、保存版本冲突检测、导入素材和导出。 |

| 小游戏适配 | `kits/minigames/` | 微信、抖音运行环境的资源、存储和视听接口。 |

## 数据读写

项目服务将分文件项目展开为运行时配置，提供给编辑器和预览。保存时仍按项目的文件结构写回，不把创作内容集中到浏览器缓存。

编辑器保存带有读取时的版本信息。文件被外部工具改动后，版本不匹配会提示冲突，避免覆盖较新的内容。图片和音视频导入项目内，配置只保存相对路径。

## 编译与执行

`source.js` 处理注释并保留源位置；`compiler.js` 解析标签、构建跳转与选择指令，检查资源、变量、目标和类型。`expression.js` 只解释受支持的运算，不执行任意 JavaScript。

`keywords.js` 将中英文关键词和参数统一为内部名称，`schema.js` 描述指令字段并生成默认中文标签。编辑器表单、补全和播放器共享这些定义。

`runtime.js` 维护变量、调用栈、舞台和当前等待。对白等待玩家确认；动画、音效和视频等待完成；弹窗等待关闭。按钮调用脚本时保存父剧情的等待，返回后恢复。

`text.js` 处理插值、行内样式、文字速度和停顿。`layout.js` 计算跨画幅背景显示。渲染器接收运行状态，并以可取消的动作实现视听表现。

## 编辑画布与真实预览

界面和背景的创作画布用于定位、缩放与属性编辑。界面画布不推进剧本，也不执行按钮事件。

预览通过嵌入的 Cocos 页面运行实际游戏。编辑器向它提供项目、测试入口与测试变量，并接收执行状态。导出的 Web 游戏使用同一套已构建播放器，因此修改故事和素材后不需要重新编译引擎。

## 导出路径

Web 导出复制已构建播放器，附上当前配置与项目素材；Creator 导出将播放器源文件、脚本内核、场景和素材整理为工程。小游戏工具包使用对应平台的预构建播放器，并整理故事分包。

新增玩法时，先判断它属于项目数据、编辑器表单，还是运行时行为。只改数据无需构建；新增标签或演出效果涉及脚本内核与 Cocos 适配，需要同步构建各个目标，详见[源码与构建](development.md)。
